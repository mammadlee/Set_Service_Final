# SET Service — Google Play Data Safety technical inventory

Status: engineering evidence for the **1.0.0+4 candidate**, not a completed Play Console declaration or legal opinion. Product/legal owners must confirm the final answers, retention periods, processors and production configuration before submission. This document supersedes the older planning assumptions in `MOBILE_STORE_PRIVACY_INVENTORY.md` where they differ from current code.

The Android source declares `INTERNET`, `CAMERA` and `POST_NOTIFICATIONS`; it does not declare `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION` or `AD_ID` in the checked source manifests. The **locally merged release manifest** was also checked and has none of those three permissions; it sets `usesCleartextTraffic=false`. `pubspec.yaml` includes `firebase_core` and `firebase_messaging`, not Firebase Analytics, Crashlytics or Google Mobile Ads. Re-check the final packaged dependency tree/configuration before completing Play Console because the local checkout has no `google-services.json` and the actual release Firebase setup was not verified.

In the table, “shared” means available to another legitimate user/role or a service processor; it does not imply advertising or sale. “Deletion” describes implemented account deletion, not an unconditional deletion of all transactional or audit records. API traffic uses HTTPS/TLS in the configured production mobile URL; private files use authorized short-lived downloads. Verify the deployed infrastructure separately.

## Legal acceptance implementation decision

New Worker and Company registration screens display working Terms/Privacy links and require the consent checkbox before sending the registration request. Existing approved users receive a one-time, account-scoped local consent gate. The backend does **not** currently store a versioned `accepted_at` record or independently reject older clients that omit consent. No new mandatory API field was added in this candidate because it would break already-installed registration clients before a coordinated mobile/backend rollout; Play submission can present the in-app notice and acceptance flow without asserting server-side audit proof. If SET Service needs enforceable contractual evidence of acceptance, legal/product must approve a versioned server-side consent record and a backward-compatible rollout before launch. Do not describe the current local checkbox as a durable backend audit trail.
